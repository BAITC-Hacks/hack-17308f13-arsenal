# Security review: «Аким на 5 часов»

Дата: 23 сентября 2026. Объект: текущая рабочая копия репозитория, включая незакоммиченные изменения. Это обзор кода и локальные проверки, не penetration test опубликованного сервиса.

## Вывод

Перед публичным включением платного AI необходимо закрыть неавторизованный доступ и организовать общий контроль расходов. Для локального демо с выключенным AI эти финансовые риски не активны. Текущее значение `AI_ENABLED` не проверялось: секретные файлы не читались.

## Подтверждённые находки

### 1. Высокий риск: платный endpoint доступен без авторизации

**Место:** `lib/server/analyze.ts:29–97`, `app/api/analyze/route.ts`.

При включённом AI и настроенном ключе любой клиент, имеющий сетевой доступ к `/api/analyze`, может отправить допустимый план и инициировать OpenAI-вызов. Проверки пользователя, сессии или права на расходование API-кредитов нет. ID мероприятий публичны; разные допустимые планы позволяют получать промахи кэша.

**Последствия:** расход средств владельца ключа и исчерпание общей квоты, после чего легитимным пользователям возвращается 429. Это не утечка самого ключа: вызывается серверный провайдер за его счёт.

**Подтверждение:** локальный тест с фиктивной конфигурацией и мок-провайдером получил HTTP 200 и один вызов провайдера без авторизации. Реальный OpenAI не вызывался.

**Исправление:** до публичного включения использовать серверную авторизацию или защиту доступа на прокси; добавить квоты на пользователя и общий бюджет запросов/расходов. Секретный токен, встроенный в публичный клиент, защитой не будет.

### 2. Средний риск: лимиты не объединяются между процессами

**Место:** `lib/server/request-limits.ts:2–31`, `lib/server/analyze.ts:80–90`.

6 стартов в минуту, 2 параллельных вызова и кэш хранятся в памяти конкретного процесса. Другой экземпляр имеет независимую квоту; рестарт обнуляет состояние. Лимит частоты не является дневным или денежным пределом. Он также общий для всех посетителей одного экземпляра, без справедливого распределения по пользователям.

**Подтверждение:** после исчерпания лимита одного `RequestLimits` новый экземпляр допускает запрос к мок-провайдеру.

**Исправление:** атомарный общий лимитер для всех экземпляров, квоты пользователей и глобальная остановка по бюджету. При недоступности лимитера платные вызовы должны блокироваться. Ограничения расходов у провайдера следует настроить отдельно.

### 3. Средний риск: посторонняя страница может инициировать расходный запрос

**Место:** `lib/server/analyze.ts:47–61`.

Обработчик не проверяет `Origin` и `Content-Type`: JSON разбирается независимо от MIME-типа. Запрос с чужим Origin и `Content-Type: text/plain` принимается как обычный. Такой тип позволяет браузеру отправить простой cross-origin POST без предварительного OPTIONS. Запрет чтения ответа через CORS не предотвращает серверную обработку и расход кредита.

**Подтверждение:** тест передал чужой Origin и `text/plain` с валидным JSON; обработчик вернул 200 и вызвал мок-провайдер. Проверен обработчик, а не поведение конкретного браузера, прокси или опубликованного домена.

**Исправление:** требовать `application/json`, проверять допустимый Origin для браузерного потока; при cookie-авторизации предусмотреть CSRF-защиту. Это дополнительная защита: прямой HTTP-клиент может подделать Origin, поэтому она не заменяет исправление №1.

### 4. Средний риск, зависит от хостинга: нет тайм-аута чтения тела запроса

**Место:** `lib/server/request-limits.ts:32–59`, `lib/server/analyze.ts:49,87`.

Размер тела ограничен 8 КБ, но `reader.read()` может ожидать следующий фрагмент без прикладного дедлайна. Лимит параллельности берётся только после полного чтения и валидации. Медленные незавершённые тела могут удерживать ресурсы до вмешательства HTTP-сервера или прокси. Тайм-аут OpenAI 25 секунд на это ожидание не распространяется.

**Подтверждение:** тест с управляемым потоком и виртуальным временем показал, что чтение остаётся незавершённым после 60 секунд; затем поток был штатно завершён. Сетевая нагрузочная атака не проводилась.

**Исправление:** настроить тайм-ауты чтения/соединения и ограничения входящих запросов на прокси; добавить отмену чтения по прикладному дедлайну и сигналу отключения клиента. Эффективные ограничения хостинга отдельно не проверялись.

## Что уже защищено

- Ключ используется в серверном модуле с `server-only`; клиент отправляет только план.
- Zod отклоняет дополнительные поля и неизвестные ID. Сервер повторно проверяет бюджет, состав и конфликты, сам рассчитывает показатели.
- Ограничение 8 КБ проверяется по фактически прочитанному телу, в том числе без Content-Length.
- URL провайдера и модель не управляются входным запросом; пользовательский произвольный prompt не принимается.
- AI возвращает ограниченные ID фактов; сервер проверяет их существование и категории. Альтернативный план проходит валидатор и симулятор.
- Ответы UI выводятся как React-текст, без `dangerouslySetInnerHTML`. Тест с HTML-подобным ответом не даёт ему выполниться как HTML.
- Ошибки провайдера не отправляются клиенту в исходном виде; ответы endpoint имеют `Cache-Control: no-store`.
- Тайм-аут OpenAI — 25 секунд, автоматические повторы выключены, выход ограничен 1400 токенами.
- `.gitignore` исключает `.env*`, кроме `.env.example`, а также `.pem` и `.key`. Среди отслеживаемых файлов и путей доступной Git-истории по этим маскам найден только `.env.example`. Это не доказывает отсутствие секретов под другими именами или в недоступной истории.

## Выполненные проверки

- Статический обзор endpoint, лимитера, схем, серверного AI-модуля, клиентского запроса и вывода UI.
- Все 74 существующих теста прошли.
- Три временных теста воспроизвели: неавторизованный запрос с чужим Origin/text/plain; независимость квот процессов; отсутствие дедлайна чтения тела. Использовались только моки. Тесты не добавлены в постоянный набор, поскольку закрепляют небезопасное поведение как ожидаемое.
- `npm audit` успешно обратился к реестру npm и сообщил **0 известных уязвимостей** для проверенного дерева зависимостей. Это не исключает неизвестных уязвимостей или ошибок приложения.
- Версии из lockfile: Next.js 16.3.6, React/React DOM 19.3.0, OpenAI SDK 6.49.0, Zod 4.6.5.

## Границы проверки

Секретные env-файлы и реальные ключи не читались; конфигурация AI не проверялась реальным вызовом. Не проверены публичный хостинг, HTTPS, заголовки прокси, WAF, настройки аккаунта OpenAI и ограничения бюджета провайдера. Браузерный pentest и нагрузочные запросы не выполнялись. Проверка Git ограничена именами файлов, без полного сканирования содержимого истории на секреты.

В рамках review код приложения не менялся. Уязвимости выше **не исправлены**. Push и deploy не выполнялись.
