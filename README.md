# Аким на 5 часов

Пять решений для лучшего города. Рабочий локальный MVP для задачи Astana Innovations: выберите пять мероприятий, распределите 100 условных единиц и сравните состояние пяти условных районов через восемь кварталов. Данные синтетические; результат **не является прогнозом развития Астаны**.

## Быстрый запуск

Требуется Node.js 22.12+ (ветка 22), 24 или 26+ и npm. В корне репозитория:

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Без настройки окружения весь математический симулятор работает, AI выключен.

Production:

```bash
npm run build
npm run start
```

## Настройка настоящего AI

Скопируйте шаблон локально:

```bash
cp .env.example .env.local
```

Имя файла должно быть точно `.env.local`, без пробелов. Файлы `.env. local` и `.env.` не заменяют его.

В редакторе заполните `.env.local`: `OPENAI_API_KEY` — ключ проекта команды; `OPENAI_MODEL` — точный ID модели, доступной этому проекту и поддерживающей Responses API; `AI_ENABLED=true`. Перезапустите сервер. Ключ не передавайте в чат или Git. Доступность моделей проверяйте в [проекте OpenAI](https://platform.openai.com/settings/organization/projects) и [каталоге моделей](https://developers.openai.com/api/docs/models). Приложение намеренно не выбирает модель за команду.

Интеграция использует официальный пакет `openai` и [Responses API](https://developers.openai.com/api/docs/guides/text): серверные `instructions`, `input`, `max_output_tokens`, чтение `output_text`. `store: false`, тайм-аут 25 секунд, автоматические повторы отключены, выход ограничен 1400 токенами (включая reasoning). Незавершённый ответ считается ошибкой, его можно запросить повторно.

После перехода на экран результата LLM автоматически объясняет готовую математику: сильные стороны, оставшиеся проблемы, компромиссы, рекомендации. Score отображается сразу, до завершения запроса. LLM не рассчитывает Score и не изменяет эффекты. Обычный ререндер, возврат назад и повторное открытие того же результата не отправляют новый запрос; при ошибке доступна кнопка «Повторить». Передаются только синтетические данные сценария. Ошибки конфигурации или провайдера не мешают симуляции; шаблонный текст не выдаётся за AI. Изменение выбора очищает результат и AI-анализ, запоздавшие ответы игнорируются.

## Правила и формула

- Ровно пять различных мер, стоимость не выше 100, не более двух мер каждого направления. Все пять направлений охватывать необязательно.
- Районная мера требует существующий район; городская применяется ко всем районам и не принимает район.
- M1 и M3 несовместимы при любых районах; M4/M7 и M5/M13 несовместимы только в одном районе.
- Реализованный эффект: `fullEffect × (8 − lag) / 8`, включая отрицательные эффекты.
- Фиксированные синергии: M1+M2 → T1 +2 в районе M1; M10+M12 → B1 +2 в районе M10; M5+M6 → E2 +2 в районе M5.
- После суммирования эффектов и синергий каждый показатель ограничивается 0–100. Исходные данные не меняются, каждый расчёт начинается заново.
- Районный балл `D = Σ(weight × indicator)`. Веса T1/T2/E1/E2/S1/S2/B1/B2/C1/C2: 0.10/0.10/0.09/0.11/0.11/0.11/0.09/0.09/0.10/0.10.
- `D_avg = Σ(populationShare × D)`. Доли населения: Есиль .27, Алматы .24, Сарыарка .20, Байконур .13, Нура .16.
- `N_crit` — число пар район/показатель строго ниже 40. Ровно 40 не критично.
- `Score = 0.7 × D_avg + 0.3 × min(D) − N_crit`. Сам Score не ограничивается 0–100; остаток бюджета не даёт бонуса. Округление только при отображении.

Разложение прироста: `0.7 × ΔD_avg`, `0.3 × Δmin(D)`, `N_crit_before − N_crit_after`. Отдельные меры меняют показатели, но не имеют аддитивного вклада в нелинейный Score.

## Структура

- `app/` — Next.js App Router, страница, стили Tailwind/CSS, серверный `POST /api/analyze`.
- `components/Simulator.tsx` — переходы между тремя шагами и состояние плана. `MeasureCatalog`, `PlanSummary`, `DistrictPicker`, `ScenarioResults`, `AiAdvisor` — части интерфейса; `Modal` использует нативный HTML dialog.
- `lib/ai-client.ts` — привязка AI-запроса к сценарию, защита от дублей и поздних ответов.
- `data/` — точный типизированный датасет, меры, правила, пример.
- `lib/simulate.ts`, `validate.ts`, `scenario-schema.ts` — общий детерминированный расчёт и строгая схема Zod.
- `lib/server/` — OpenAI, обработчик API, лимиты; изоляция через `server-only`.
- `tests/` — содержательные проверки математики, валидации, API с замоканным провайдером; API-кредиты не расходуются.

## Безопасность и ограничения

`POST /api/analyze` принимает исключительно `{ "decisions": [...] }` с полным набором пяти решений. Строгая схема отклоняет лишние поля, неизвестные ID и неправильные типы. Поток тела ограничен 8 КБ независимо от Content-Length. Сервер сам проверяет правила и пересчитывает сценарий. Клиент не задаёт Score, цены, модель, prompt или API URL. Ответы ошибок не содержат исходных ошибок провайдера; секреты не логируются.

AI по умолчанию выключен. На процесс разрешены 6 новых вызовов в минуту и 2 одновременно. Кэш на 100 записей с TTL 10 минут учитывает нормализованный сценарий, версию данных и модель. Попадание в кэш не вызывает провайдера. При изменении данных/формулы/инструкции анализа обновите `DATA_VERSION`.

Лимиты и кэш находятся в памяти, сбрасываются при рестарте и **не являются общим лимитом для нескольких экземпляров**. Перед публичным включением платного endpoint необходимы защита доступа и общий серверный лимит расходов, а также лимиты бюджета проекта у провайдера. CORS не защищает расходы. Это локальное демо без регистрации, базы данных и внешней аналитики.

`.env.local`, ключи и локальный TASK.md исключены из Git. Если ключ когда-либо оказался в истории Git, его необходимо отозвать; удаление файла не очищает историю.

Модель не учитывает инфляцию, рост населения, макроэкономику и реальные сроки/стоимости. AI может ошибаться, его рекомендации нужно проверять симулятором. Нельзя использовать результаты как обоснование реального управленческого решения.

## Пользовательский сценарий и демо за две минуты

1. **Собрать план.** Выберите мероприятия в каталоге. У районной меры нажмите «Выбрать район»: окно покажет пять районов, относящиеся к мере исходные показатели и критические значения. Подтвердите район. Для городской меры достаточно «Добавить в план».
2. В блоке «Ваш план» видны бюджет, остаток и выбранные меры. На телефоне сводка закреплена снизу, полный план открывается кнопкой «Ваш план». Район можно изменить, мероприятие — удалить. Недоступные действия сопровождаются причиной; несовместимые районы нельзя подтвердить.
3. Для быстрого демо нажмите **«Загрузить пример»**: пять решений на 95 единиц. Если план уже заполнен, приложение спросит о замене. Исходные проблемы районов и Score 52,56 доступны в раскрываемом блоке.
4. **Проверить план.** Кнопка становится доступна только для полного валидного плана. Проверьте пять мер, районы, стоимость и совместный эффект освещения с цифровой платформой обращений.
5. **Рассчитать результат.** Откроется отдельный экран: **52,56 → 56,54 (+3,99)**, критические показатели **2 → 0**. Появятся районные изменения, оставшиеся проблемы и подробная формула. Страница прокручивается к началу, фокус переходит на заголовок.
6. AI-разбор начинается автоматически, отдельно от расчёта. Если AI выключен или не настроен, показан честный статус. При ошибке нажмите «Повторить». Тесты используют моки — они не подтверждают реальный вызов OpenAI.
7. Нажмите **«Изменить план»**, измените район школы и повторите проверку и расчёт. Возврат назад сохраняет выбор; изменение решения сбрасывает старый результат и AI-разбор. Ответ предыдущего запроса не появится в новом сценарии.
8. **«Начать заново»** требует подтверждения. Для демонстрации ограничений выберите автобусные полосы: ЛРТ станет недоступной с объяснением. Добавление третьей меры направления, шестого мероприятия и превышение бюджета также блокируются.

На desktop план закреплён справа и прокручивается внутри, если он выше экрана. На мобильной ширине предусмотрены нижний отступ и safe area. Диалоги поддерживают Escape, кнопку закрытия, удержание и возврат фокуса. Переходы между шагами не требуют повторного выбора мер.

### Проверки нового UX

`npm run test` включает DOM-тесты React в jsdom: три шага, сохранение выбора, районные диалоги, подтверждение сброса, состояния AI и игнорирование старого ответа. AI полностью замокан; кредиты не расходуются. Отдельно проверяются промежуточная валидация, замена района и клиентская защита запросов. jsdom не выполняет визуальный layout и не заменяет проверку нативного dialog в браузере.

Браузерная проверка desktop/mobile в текущей сессии недоступна. Перед демонстрацией вручную проверьте ширины телефона и ноутбука, Tab/Shift+Tab/Escape в диалоге, видимость нижней панели и возврат фокуса.

## Перед публичной публикацией

- Подтвердить право публичного распространения материалов организаторов: разрешение пока не установлено.
- Настроить защиту платного endpoint и общие лимиты, проверить доступность выбранной модели реальным запросом.
- Проверить секреты в файлах и истории без вывода значений; при обнаружении отозвать ключ.
- Провести браузерную проверку на целевых устройствах.

Push, публикация сайта и изменение видимости репозитория не выполняются автоматически.
